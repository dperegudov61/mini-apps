# Game engine — каркас графического движка на WebGPU

Мини-приложение проекта Mini Apps: страница только грузит файлы, шейдер (WGSL) и скрипты
лежат отдельно, вывод шейдера показывается в рамке.

Адрес: <https://dperegudov61.github.io/mini-apps/apps/game-engine/>

Луч на каждый пиксель считается на GPU аналитически (точные пересечения с аналитическими
телами, без марша по объёму). Сцены — наборы объектов, окружения и камеры — собираются
на процессоре: шейдер о них ничего не знает, он получает готовые примитивы и числа.

Сцен сейчас две: **стенд** (пьедестал, ступени, обелиски, парящий куб, сферы на орбитах)
и **бенчмарк** (куб 16×16×16 из сфер, которые появляются по одной — проверка нагрузки
и стабильности).

## Как запускать

* **По адресу выше** — основной путь: ничего не собирается, Pages отдаёт файлы как есть,
  правка в репозитории видна после `git push` и обновления страницы (≈1 минута на сборку Pages).
* Локально — только через `http` (любой статический сервер в папке `mini-apps/`).
  Двойным щелчком по `index.html` с диска **не запустится**: браузер не даёт читать соседние
  файлы (`fetch` шейдеров заблокирован), страница честно об этом скажет.
  Серверных файлов внутри приложения нет — это чистая статика.

Нужен браузер с WebGPU: Chrome или Edge 113+. Нет адаптера — подсказки на самой странице
покажут причину.

## Управление

| действие | что делает |
|---|---|
| перетаскивание мышью / пальцем | камера облетает цель |
| колесо | приближение и отдаление |
| `W` `A` `S` `D` | двигают цель по земле |
| `Q` `E` | цель вниз / вверх |
| стрелки | поворот камеры |
| «Сброс» | ползунки **этой** сцены и камера — к значениям по умолчанию, замеры заново |
| «Пауза» | сцена замирает (камера, ползунки и замеры продолжают работать) |

Камера у каждой сцены своя: её начальное положение описано в `camera` описания сцены.

## Сцены

Сцена — это независимый набор:

* **объектов** — массив `{kind: 'sphere' | 'cone' | 'box', …}`;
* **параметров окружения** — высота солнца, яркость, звёзды, разметка земли;
* **камеры** — цель, поворот, расстояние, угол обзора;
* **своих ползунков и переключателей** — у каждой сцены свой набор, свои значения
  и своя память (`scene.<id>` в `localStorage`).

Общее для всех сцен — только **настройки рендера** (масштаб кадра, авто-масштаб, тени)
и инструменты производительности. Они лежат в отдельном блоке панели и в отдельном ключе
памяти (`gfx`).

Устройство:

```
js/scene/registry.js   реестр: GE.Scenes.define({...}) — описание сцены и фабрика create()
js/scene/pack.js       солнце (GE.sunFor) и упаковка сцены в буферы (GE.packObjects, GE.writeFrame)
js/scene/demo.js       сцена «стенд»     → GE.Scenes.define({ id: 'demo',  … })
js/scene/bench.js      сцена «бенчмарк»  → GE.Scenes.define({ id: 'bench', … })
```

Описание сцены:

```js
GE.Scenes.define({
  id: 'demo',                       // ключ в памяти и в списке
  label: 'game-engine.sceneDemo',   // ключ надписи (strings.tsv), fb — английский запас
  note: 'game-engine.sceneDemoNote',
  camera: { target: [0, 1.5, 0], yaw: 0.75, pitch: 0.32, distance: 12.5 },
  params:  [GE.SceneParts.sun(30), GE.SceneParts.speed(1), GE.SceneParts.exposure(1)],
  toggles: [GE.SceneParts.stars(1), GE.SceneParts.grid(1)],
  actions: [],                      // свои кнопки: у бенчмарка — «заполнить сразу»
  create: function () { return new DemoScene(); }
});
```

Живой набор объектов, который отдаёт `create()`, обязан уметь немного:

| поле / метод | смысл |
|---|---|
| `objects` | массив примитивов, который каждый кадр уезжает на GPU |
| `env` | `{sunHeight, exposure, stars, grid}` — значения окружения кадра |
| `sun` | `GE.sunFor(env.sunHeight)`: направление, цвет, сила, свет неба |
| `time` | игровое время, уходит в шейдер (звёзды, дизеринг) |
| `update(dt, settings)` | движение, появление объектов; `dt = 0` — пауза |
| `reset()` | вернуть сцену в начало |
| `status(settings)` | необязательная строка состояния под панелью |

Порядок в списке на странице — порядок вызовов `define()`; подключение файлов — в конце
`index.html`. Состояние (какая сцена открыта, какие ползунки) запоминается в `localStorage`.

## Сцена «стенд»

`js/scene/demo.js`:

* пьедестал (куб) и сфера на нём — центр композиции;
* три ступени из кубов, уходящие вправо;
* парящий куб, качающийся по высоте;
* три конуса-обелиска по краям;
* три сферы, летающие по орбитам разного радиуса и с разной скоростью.

Движение — только на процессоре: `update()` пересчитывает координаты, `packObjects()`
раскладывает их по буферу, шейдер о времени и орбитах ничего не знает.
Ползунки: высота солнца (−90…+90°), скорость анимации, яркость; переключатели: звёзды,
разметка земли.

## Бенчмарк «куб сфер 16×16×16»

`js/scene/bench.js`: 4096 сфер (`16³`) с шагом сетки 1 м и радиусом 0.30 м, центр куба —
на высоте 8 м. Сферы появляются по одной, слой за слоем снизу вверх, поэтому рост нагрузки
видно глазом: 1, 2, 3… сферы в секунду (ползунок «сфер в секунду», 1…100). Кнопка
«заполнить сразу» ставит все 4096 без ожидания.

Зачем: это проверка движка и сбор данных о стабильности. Число примитивов растёт от 0 до
4096, и по графику времени кадра видно, держит ли движок нагрузку ровно, где появляются
ступеньки и рывки. Потолок буфера примитивов — 4096 (`MAX_PRIMS` в `js/gfx/renderer.js`,
192 КБ), столько же считает шейдер.

Замеры на этом стенде (nvidia pascal, один и тот же кадр, сферы все 4096, тени включены):

| масштаб | разрешение | среднее время кадра | fps |
|---|---|---|---|
| 0.5× | 258×145 | ≈ 19.6 мс | ≈ 50 |
| 1× | 516×290 | ≈ 63.7 мс | ≈ 16 |
| 2× | 1032×581 | ≈ 146 мс | ≈ 7 |

Время растёт ровно вчетверо на каждом шаге масштаба: цена кадра — это пиксели × примитивы.
Ползунки сцены: скорость появления, высота солнца, яркость; переключатели: звёзды, сетка.

## Настройки рендера (общие для всех сцен)

* **масштаб рендера** — кадр считается в 0.01…2× от размера полотна: главный рычаг нагрузки
  (лучи считаются на каждый пиксель);
* **авто-масштаб** — сам держит кадр около 60 Гц, меняя разрешение множителем (×0.7 вниз,
  ×1.2 вверх за полсекунды) в тех же пределах до **0.01×** — на таком пределе от картинки
  остаются единицы пикселей, зато видно нижнюю границу цены кадра;
* **тени** — лучи к солнцу; самая дорогая часть кадра, особенно на 4096 примитивах;
* **отладка поверх кадра** — зелёная строка в левом верхнем углу рамки (fps, время кадра,
  p95, худший, разрешение, масштаб, число примитивов, cpu/gpu); галочка убирает её,
  панель с теми же цифрами остаётся на месте.

## Инструменты производительности

* **отладка поверх кадра** — та же сводка контрастно-зелёной строкой в левом верхнем углу
  рамки: видно, не отрываясь от картинки (галочка «отладка поверх кадра» в настройках рендера),
  и одновременно в панели ниже — полные цифры и график;
* **график времени кадра** — по горизонтали последние 180 кадров (≈3 с), по вертикали
  миллисекунды; линия 60 Гц сплошная, 30 Гц — пунктир;
* **цифры**: fps, среднее время кадра, лучший и худший кадр за окно, 95-й процентиль
  (по нему видно рывки, которые среднее прячет), время процессора в кадре (cpu, мс) и
  время прохода на GPU (gpu, мс).

Время GPU берётся из `timestamp-query`: две метки вокруг прохода рендера, результат читается
обратным копированием. Не всякий браузер это разрешает: у нового Chromium метка ставится на
кодировщике команд, у части версий — только внутри прохода (и только с экспериментальной
фичей). Если нельзя ни так, ни так — в колонке `gpu` честно стоит «—», остальные измерения
работают.

## Как данные идут на GPU

Два буфера, оба заполняются из `js/scene/pack.js → GE.writeFrame()` — это единственное
место, где задан порядок значений. Сцена приходит туда обычными числами.

**1. Uniform-буфер `Params` (40 float = 160 Б, `shaders/params.wgsl`):**

| float | поле | смысл |
|---|---|---|
| 0–1 | `resolution` | размер кадра в пикселях |
| 2 | `fov` | вертикальный угол обзора, радианы |
| 3 | `time` | игровое время сцены |
| 4–7 | `camPos` | позиция камеры |
| 8–11 | `camForward` | направление взгляда |
| 12–15 | `camRight` | вправо |
| 16–19 | `camUp` | вверх |
| 20–23 | `sunDir` | направление на солнце |
| 24–27 | `sunColor` | цвет солнца + сила (0 — под горизонтом) |
| 28–31 | `skyAmbient` | цвет скайбокс-света (день/ночь считает CPU) |
| 32–35 | `counts` | сколько сфер, конусов, кубов (u32) |
| 36–39 | `extra` | яркость, тени (0/1), звёзды (0/1), разметка земли (0/1) |

Цвет и сила солнца, цвет неба — считаются на процессоре по углу солнца (`GE.sunFor`),
поэтому закат и ночь — это не ветки в шейдере, а числа.

**2. Storage-буфер примитивов (`shaders/primitives.wgsl`):** один примитив = 3 × `vec4`
(48 Б), порядок в буфере — все сферы, затем конусы, затем кубы, смещения берутся из `counts`.

| примитив | `a` | `b` | `c` |
|---|---|---|---|
| сфера | центр + радиус | — | цвет |
| конус | точка A + радиус A | точка B + радиус B | цвет |
| куб | min (AABB) | max (AABB) | цвет |

Потолок буфера — 4096 примитивов (`MAX_PRIMS` в `js/gfx/renderer.js`), в сцене-стенде
занято 12, в бенчмарке — до 4096. Сцена упаковывается каждый кадр: 4096 примитивов — это
48 К float, загрузка буфера ≈192 КБ на кадр (около 0.6 мс процессора).

## Что внутри шейдера

Шейдер — перенос HLSL-версии (`raymarch.fx`) на WGSL. Осталось:

* хеши (`hash11`, `hash21`, `hash31`);
* звёздное небо: сетка ячеек по направлению луча, в каждой ячейке своя звезда;
* небо: градиент, закатная полоса у горизонта, диск солнца, ореол, рассеяние;
* земля: бесконечная плоскость `y = 0` с клетчатой сеткой, линии толще вдали;
* примитивы: сфера, усечённый конус (боковая поверхность + два торца), куб как готовый AABB;
* свет: скайбокс-свет + прямое солнце с жёсткой тенью + слабый блик и обводка;
* дымка к горизонту и дизеринг против полос на градиентах.

**Убрано насовсем** (по требованию к адаптации): все полупрозрачные объекты — призрачный
материал, аура из отрезков со слиянием стыков, поглощение `exp(-σ·d)`, цветные тени сквозь
оболочки, счётчики прозрачных слотов. Все тела непрозрачные, тени — жёсткие.

**Перенесено на CPU** (дороже на GPU, чем нужно): 4D-срез, поворот куба (в буфер едет уже
готовый осевой AABB), цвет и сила солнца, цвет неба, матрица/базис камеры.

## Что делать дальше (порядок предложен)

1. **Разные шейдеры на разные сцены**: сцена указывает свой `.wgsl`, рендерер пересобирает пайплайн.
2. **Постобработка отдельным проходом**: свечение, тонмаппинг.
3. **Буфер глубин и треугольники**: пройтись по сцене обычной растеризацией рядом с лучами
   и сравнить картинку — проверка «CPU ↔ GPU» на настоящих моделях.
4. **Текстуры с картинки**: `fetch` + `createImageBitmap` + `copyExternalImageToTexture`.
5. **Мягкие тени** вместо жёстких: несколько лучей на пиксель к диску солнца.
6. **Ускорение большого числа примитивов**: сетка/октодерево или экземпляры (instancing) —
   сейчас 4096 сфер перебираются на каждый луч, и это ровно то, что меряет бенчмарк.

## Рецепты правок

* **Новая сцена**: файл `js/scene/<id>.js` по образцу `demo.js` с `GE.Scenes.define({...})`,
  подключить его в конце `index.html` **после** `registry.js` и `pack.js`, добавить две
  надписи (`scene<Id>`, `scene<Id>Note`) в `strings.tsv`.
* **Свой набор ползунков**: собрать `params` и `toggles` в `define()` из `GE.SceneParts`
  или описать свои — `{key, label, fb, min, max, step, def, fmt}`; значения сцена получает
  в `update(dt, settings)`.
* **Кнопка сцены**: `actions: [{ key, label, fb, run: function (scene, settings) { … } }]`.
* **Новый объект в сцене**: дописать в `objects` — упаковка и счётчики подхватят его сами,
  пока не упрётесь в `MAX_PRIMS` (4096).
* **Другое положение камеры при открытии**: `camera: {target, yaw, pitch, distance, fov}`.
* **Новое значение с процессора**: поле в конец `Params` в `shaders/params.wgsl`, поднять
  `PARAMS_FLOATS` в `js/gfx/renderer.js`, записать значение в `pack.js → GE.writeFrame()`.
* **Новый переключатель нагрузки**: свободное поле в `extra` (`shaders/params.wgsl`) → ветка
  в `scene.wgsl` → значение в `writeParams` (в `pack.js`) → переключатель в `toggles` сцены
  или в `GFX_TOGGLES` (`js/ui/panels.js`), если он общий для всех сцен.
* **Новая строка статистики**: ячейка `<b>`/`<i>` в блоке `.perf-stats`, ссылка в `this.el`
  и заполнение в `HUD.setPerf()`.
* **Новая надпись**: ключ в разметку/код + строка в `strings.tsv`.
* **Новый цвет**: сначала пара переменных в `:root` и `html[data-theme="light"]` в `app.css`,
  в правилах — только `var(--…)`.

## Грабли

* `file://` не работает — только веб-адрес или локальный `http`.
* `timestamp-query` — фича необязательная. Если браузер не даёт поставить метки ни на
  кодировщике, ни внутри прохода, `gpu` показывает «—», а остальные цифры остаются верными.
* Время кадра — интервал между `requestAnimationFrame`, а не время работы GPU. Для fps
  берётся настоящий интервал (не ограниченный шагом сцены), поэтому на тяжёлых кадрах
  цифра честная; кадры после переключения вкладки (сотни миллисекунд) в статистику не берутся.
* Шаг сцены ограничен 50 мс: после паузы или подвисания сцена не прыгает вперёд.
* Номера строк в ошибках шейдера считаются по склеенному тексту (с вставленными
  `params.wgsl` и `primitives.wgsl`).
* Uniform-структура выравнивается по 16 байт: `vec2f` + два `f32` дают 16 Б, дальше только
  `vec4f`; `counts` — `vec4u` и пишется через `Uint32Array` поверх того же буфера.
* В WGSL нет тернарного `?:` (есть `select`), нет сложения вектора с числом
  (`vec3f * scalar` — да, `vec3f + scalar` — нет) и `smoothstep` с обратными краями
  даёт мусор — в шейдере все такие места переписаны через `1.0 - smoothstep`.
* Канвас создаётся только с `RENDER_ATTACHMENT`: чтение кадра обратно на CPU больше не нужно.
* Память настроек (`localStorage`, префикс `miniapps.game-engine.`): `gfx` — настройки
  рендера, `scene.<id>` — ползунки сцены, `activeScene` — какая сцена открыта. Старый общий
  ключ `settings` при первом запуске разбирается на эти три и удаляется.
* 4096 сфер на каждый луч — это честно дорого: полный куб на масштабе 2× даёт ~7 fps даже
  на дискретной карте. Для бенчмарка это ожидаемо; для игры столько объектов нужно
  ускорять структурой (сетка, октодерево, экземпляры).
