# Game engine — каркас графического движка на WebGPU

Мини-приложение проекта Mini Apps: страница только грузит файлы, шейдер (WGSL) и скрипты
лежат отдельно, вывод шейдера показывается в рамке. Заготовка для дальнейшей разработки:
всё, что нужно для роста, уже разложено по файлам.

Адрес: <https://dperegudov61.github.io/mini-apps/apps/game-engine/>

## Как запускать

* **По адресу выше** — основной путь: ничего не собирается, Pages отдаёт файлы как есть,
  правка в репозитории видна после `git push` и обновления страницы (≈1 минута на сборку Pages).
* Локально — только через `http` (любой статический сервер в папке `mini-apps/`).
  Двойным щелчком по `index.html` с диска **не запустится**: браузер не даёт читать соседние
  файлы (`fetch` шейдеров и ES-файлов заблокирован), страница честно об этом скажет.
  Серверных файлов внутри приложения нет — это чистая статика.

Нужен браузер с WebGPU: Chrome или Edge 113+. Нет адаптера — панель проверки и подсказки
на самой странице покажут причину.

## Файлы

```
index.html            разметка: рамка, канвас, метрики, панель. Логики нет
app.js                точка входа: GPU → рендерер → игра → проверка, цикл кадров
app.css               стили (цвета только через переменные палитры, тёмная и светлая)
app.json              паспорт мини-приложения
strings.tsv           таблица надписей (key / en / ru)
icon.png              иконка 512×512 (рисует tools\make_app_icons.ps1 основного проекта)

js/i18n.js            t() поверх общего шаблона /ui/ui.js + подстановка {0}, {1}…
js/shaders.js         загрузка .wgsl, директива //#include
js/gpu.js             адаптер, устройство, контекст, разбор ошибок компиляции
js/renderer.js        пайплайн, uniform-буфер, текстура с CPU, отрисовка кадра
js/game.js            игровая логика: мяч, отскоки, притяжение к мыши
js/input.js           мышь и палец → координаты в пикселях кадра
js/texture.js         процедурная текстура 256×256, целиком посчитана на CPU
js/selftest.js        проверка запуска шейдеров
js/hud.js             слайдеры, метрики, вывод проверок, сообщение об ошибке

shaders/params.wgsl   структура значений с процессора (16 float = 64 Б)
shaders/render.wgsl   шейдер сцены: плазма, сетка, текстура, мяч, прицел
shaders/verify.wgsl   дымовой compute-шейдер: запустился и оставил метку
```

Все скрипты — обычные (не модули), одна общая «шина» `window.GE`: так файлы грузятся
в любом окружении и порядок подключения виден в конце `index.html`.

## Как данные идут на GPU

`js/game.js → writeParams()` заполняет `Float32Array(16)`, он уходит в uniform-буфер:

| float | поле | смысл |
|---|---|---|
| 0–1 | `resolution` | размер кадра в пикселях |
| 2–3 | `mouse` | курсор в пикселях кадра |
| 4–6 | `ball` | x, y, радиус мяча (считает игровая логика) |
| 7 | `time` | игровое время |
| 8 | `hueShift` | сдвиг палитры |
| 9 | `texMix` | сколько подмешивать текстуру |
| 10 | `wave` | медленная волна |
| 11 | `frame` | номер кадра |
| 12–15 | `extra` | скорость мяча, аспект, «энергия» |

Плюс текстура 256×256 `rgba8unorm`, которую целиком считает процессор (`js/texture.js`).
Порядок полей описан один раз — в `shaders/params.wgsl`, он подключается в шейдер через
`//#include`, поэтому JS и WGSL не разъезжаются.

## Проверка запуска шейдеров

Кнопка «Прогнать тест» (и один автоматический прогон при старте):

1. **рендер-шейдер** — WGSL скомпилировался, пайплайн создан, кадр нарисован; из готового
   кадра читается полоса пикселей обратно на CPU. Шейдер ничего не нарисовал — тест красный.
2. **compute-шейдер** — `shaders/verify.wgsl` запускается одной workgroup и оставляет
   в storage-буфере метку `0x43505057`, CPU читает её обратно.

Вокруг обеих операций стоит `pushErrorScope('validation')`, поэтому ошибки валидации WebGPU
попадают в отчёт, а не только в консоль. Во время проверки кадры не рисуются.

## Что делать дальше (порядок предложен)

1. **Глубокая сверка CPU ↔ GPU** вместо дымового теста: побитовое сравнение uniform-структуры,
   чтение конкретных текселей, математика на GPU против такой же на JS. Заготовка уже была —
   сетка проверок и вывод в `js/selftest.js` рассчитаны на любое число строк.
2. **Свои проходы рендера**: несколько пайплайнов и `beginRenderPass` вместо одного кадра
   (постобработка отдельным проходом, а не в конце фрагмента).
3. **Свои текстуры с картинки**: `fetch` + `createImageBitmap` + `copyExternalImageToTexture`,
   атласы, мип-уровни, `sampler` с `mipmapFilter`.
4. **Сцена вместо одного мяча**: буфер вершин/инстансов, модель с матрицами, камера,
   глубинный буфер.
5. **Игровая логика отдельным слоем**: сущности и системы, фиксированный шаг, «мир» отдельно
   от отрисовки — тогда шейдер получает уже готовые числа, как сейчас.

## Рецепты правок

* **Свой шейдер**: положить `shaders/my.wgsl` и заменить путь в `app.js`
  (`renderer.init('./shaders/render.wgsl')`).
* **Новое значение с процессора**: поле в конец `Params` в `shaders/params.wgsl`, увеличить
  `PARAMS_FLOATS` в `js/renderer.js`, записать значение в `writeParams()`.
* **Новая надпись**: ключ в разметку/код + строка в `strings.tsv` (иначе проверка
  `node tools\i18n_test.js` основного проекта ругнётся).
* **Новый цвет**: сначала пара переменных в `:root` и `html[data-theme="light"]` в `app.css`,
  в правилах — только `var(--…)` (`theme_test.js` не пропускает иначе).

## Грабли

* `file://` не работает — только веб-адрес или локальный `http`.
* Номера строк в ошибках шейдера считаются по склеенному тексту (с вставленным `params.wgsl`).
* Uniform-структура выравнивается по 16 байт — поэтому в `Params` есть `extra : vec4f`.
* `pow(x, 2.0)` при отрицательном `x` даёт NaN — в шейдере используется `x * x`.
* Канвас создаётся с `usage: RENDER_ATTACHMENT | COPY_SRC`, иначе проверка не сможет
  прочитать кадр обратно.
* Слайдеры запоминаются в `localStorage` под ключом `miniapps.game-engine.settings`.
