# Mini Apps

Маленькие самодостаточные веб-приложения в одном репозитории.

Каждое приложение — отдельная папка, открывается одним `index.html`, работает без сборки,
без сервера и без внешних библиотек. Хостинг — GitHub Pages этого же репозитория.

* Список приложений: <https://dperegudov61.github.io/mini-apps/apps.json>
* Приложение: `https://dperegudov61.github.io/mini-apps/apps/<id>/`
* Витрина — блок «Мини-приложения» на главной странице проектов: <https://dperegudov61.github.io/>
  (отдельной страницы-каталога нет — блок на главной и есть каталог)

---

## Структура репозитория

```
/
├── README.md            ← этот файл: правила и инструкции
├── .nojekyll            ← не удалять: без него GitHub прогоняет файлы через Jekyll
├── apps.json            ← список приложений (его читает главная страница проектов)
├── apps/
│   └── <id>/            ← одно приложение = одна папка
│       ├── index.html   ← главный файл, точка входа
│       ├── app.js       ← само приложение (код)
│       ├── app.css      ← стили
│       ├── app.json     ← паспорт приложения
│       ├── icon.png     ← иконка приложения
│       └── data/        ← ассеты приложения (только если нужны)
└── templates/
    └── basic/           ← заготовка нового приложения (копировать, не менять)
```

## Правила

### 1. Папка приложения

* Одно приложение — одна папка `apps/<id>/`.
* `<id>` — латиница в нижнем регистре, цифры и дефис: `snake`, `2048`, `color-picker`.
  Совпадает с `id` в `app.json` и с папкой. **Менять `id` нельзя** — ломаются ссылки,
  записи в каталоге и сохранённые данные в браузере.
* В `apps/` не кладём ничего, кроме папок приложений.

### 2. Файлы приложения

| файл | обязателен | что это |
|---|---|---|
| `index.html` | да | главный файл, единственная точка входа |
| `app.js` | да | код приложения |
| `app.css` | да | стили (можно добавить `app2.js`, `theme.css` и т.п.) |
| `app.json` | да | паспорт: название, даты, метаданные |
| `icon.png` | да | иконка 512×512 |
| `data/` | нет | ассеты: картинки, звуки, уровни (только если есть) |

### 3. Никаких внешних зависимостей

* **Не подключать CDN**: ни `<script src="https://…">`, ни шрифты с чужих доменов,
  ни `@import url(https://…)`. Приложение должно открываться офлайн и из локальной папки.
* Свои библиотеки — файлом в папку приложения и относительной ссылкой.
* Все пути **относительные** (`app.js`, `data/level1.json`) — тогда приложение работает
  и по адресу GitHub Pages, и с диска, и в подпапке.
* Сетевые запросы — только к своему `data/`, и то по необходимости. Внешних API — нет.
* Сборки нет: что лежит в репозитории, то и исполняется.
* В корне репозитория лежит пустой файл `.nojekyll` — **не удалять**. Без него GitHub
  прогоняет файлы через Jekyll, и конструкции вроде `{{ }}` внутри кода могут быть съедены.

### 4. Изоляция

* Приложение ссылается только на файлы внутри своей папки — чужие `apps/*` не трогает.
* Общего кода между приложениями нет (никакого `/shared/`). Дублирование лучше связей.
* Данные в браузере — только через `localStorage` / `IndexedDB` с префиксом `miniapps.<id>.`,
  например `miniapps.snake.best`. Так приложения не затирают данные друг друга.

### 5. Иконка

* `icon.png`, PNG, **512×512** пикселей (допускается 256×256 и 1024×1024).
* Прозрачность разрешена, но картинка должна читаться и на светлом, и на тёмном фоне.
* Проверка простая: уменьши до 64×64 — должно быть понятно, что это за приложение.

### 6. Папка `data/`

* Только ассеты самого приложения: картинки, звуки, уровни, шрифты.
* Если ассетов нет — папку не создавать (git не хранит пустые папки).
* Имена файлов — латиницей, без пробелов: `level-01.json`, `pop.mp3`.
* Ассеты не должны быть тяжелее самого приложения: картинки — до 500 КБ, звуки — до 200 КБ.

### 7. Мобильные устройства

* В `index.html` обязательна строка
  `<meta name="viewport" content="width=device-width, initial-scale=1">`.
* Раскладка адаптивная, ничего не вылезает за экран, нет горизонтальной прокрутки.
* Если приложение управляется клавиатурой — предусмотреть тач-управление
  (кнопки, свайпы) и наоборот.
* Желательно учитывать безопасные зоны: `env(safe-area-inset-*)`.

### 8. `app.json` — паспорт приложения

```json
{
  "id": "snake",
  "name": "Snake",
  "nameRu": "Змейка",
  "description": "Classic snake game on canvas",
  "descriptionRu": "Классическая змейка на canvas",
  "created": "2026-11-25",
  "updated": "2026-11-25",
  "version": "1.0.0",
  "status": "ready",
  "entry": "index.html",
  "icon": "icon.png",
  "data": "data/",
  "tags": ["game", "canvas"],
  "meta": {}
}
```

| поле | тип | обязательно | смысл |
|---|---|---|---|
| `id` | строка | да | имя папки в `apps/`, латиница в нижнем регистре |
| `name` | строка | да | название по-английски |
| `nameRu` | строка | нет | название по-русски (если отличается) |
| `description` | строка | нет | одна строка о чём приложение (англ.) |
| `descriptionRu` | строка | нет | то же по-русски |
| `created` | `YYYY-MM-DD` | да | дата создания |
| `updated` | `YYYY-MM-DD` | да | дата последнего изменения (обновлять при каждой правке) |
| `version` | `X.Y.Z` | да | `1.0.0` — новый, `1.1.0` — новая возможность, `1.0.1` — правка |
| `status` | строка | нет | `ready` — работает, `draft` — в работе, `broken` — сломано |
| `entry` | строка | нет | точка входа, по умолчанию `index.html` |
| `icon` | строка | нет | файл иконки, по умолчанию `icon.png` |
| `data` | строка | нет | папка ассетов, по умолчанию `data/` |
| `tags` | массив | нет | метки для поиска: `game`, `tool`, `text`, `canvas` |
| `meta` | объект | нет | свободные метаданные; сейчас пустой, поля придумаем позже |

Правила для паспорта: JSON валидный (никаких комментариев и висячих запятых),
UTF-8 без BOM, даты — ISO 8601.

### 9. Список `apps.json`

Список приложений. Его читает блок «Мини-приложения» на главной странице проектов
(`dperegudov61.github.io`) и рисует плитки с иконками — своего каталога у репозитория нет.
После добавления приложения в него нужно **вручную** дописать строку:

```json
{
  "updated": "2026-11-25",
  "apps": [
    {
      "id": "snake",
      "name": "Snake",
      "nameRu": "Змейка",
      "path": "apps/snake/",
      "icon": "apps/snake/icon.png",
      "tags": ["game"],
      "created": "2026-11-25"
    }
  ]
}
```

Порядок в списке — порядок плиток в блоке на главной. Свежее — выше.

## Как добавить новое приложение

1. Скопировать заготовку: `templates/basic/` → `apps/<id>/`.
2. В `app.json` заполнить `id`, `name` (и `nameRu`), `created` = сегодня, `updated` = сегодня,
   `version` = `1.0.0`, `meta` = `{}`.
3. Написать приложение в `index.html` + `app.js` + `app.css`.
4. Нарисовать `icon.png` 512×512.
5. Если нужны ассеты — создать `data/` и положить туда.
6. Дописать запись в `apps.json` (сверху списка).
7. Проверить три вещи:
   * открывается двойным щелчком по `index.html` с диска (без сервера);
   * открывается по адресу GitHub Pages;
   * работает на телефоне (или хотя бы не разваливается).
8. Закоммитить и запушить в `main`. Pages обновится сам за минуту.

### Контрольный список перед коммитом

- [ ] папка называется как `id` в `app.json`;
- [ ] `name` (англ.) и `nameRu` заполнены;
- [ ] `created` не менялся, `updated` — сегодняшний;
- [ ] `version` поднят по смыслу правки;
- [ ] иконка 512×512 и читается в 64×64;
- [ ] нет ссылок на внешние домены;
- [ ] нет мусора: `.tmp`, логи, тестовые картинки;
- [ ] запись есть в `apps.json`;
- [ ] `app.json` проходит проверку JSON.

## Тестовое приложение

`apps/snake/` — «Змейка»: проверяет, что схема выше рабочая.

* управление: стрелки / WASD, `пробел` — пауза, `R` — заново;
* на телефоне: свайпы по полю или кнопки-стрелки;
* рекорд хранится в `localStorage` под ключом `miniapps.snake.best`;
* ассетов нет: папка `data/` пока пустая и держится в git файлом `.gitkeep`.

в браузере пользователя.
